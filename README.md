# Appeals Copilot

Appeals Copilot helps a fictional healthcare practice organize synthetic insurance
claim denials, identify a next step, and draft a reviewable appeal letter. Denials
are classified from remittance adjustment codes, then matched against versioned
fictional payer policies and clinical-note evidence so staff can prioritize the
work queue and see why a case was routed.

## Architecture

```text
Synthetic X12 835 / JSON
          |
          v
    Parser + CARC table ------> In-memory case store
          |                              |
          v                              v
    Payer rules ---> Evidence matcher -> Triage -> Queue / API
                                                 |
                                                 v
                                  Deterministic Jinja2 appeal draft
```

## Quickstart

```bash
pip install -e '.[dev]'
uvicorn appeals.api:app --reload
python eval/run_eval.py
pytest
```

The API queue is available at `http://127.0.0.1:8000/api/queue`; the interactive
API documentation is at `/docs`. The root page (`/`) is the work-queue UI, with
stats, a filterable queue, denial details with criteria evidence, draft-letter
approve/download controls, and an 835 upload form.

## Rules as code

Payer deadlines, appeal destinations, policy versions, covered CPT codes, and
clinical criteria live in validated YAML files under `rules/payers/`. The CARC
category map is in `data/carc_codes.yaml`. Triage is deterministic: it applies
the adjustment category, available evidence, authorization/timely-filing facts,
and remaining appeal time to recommend an action and estimate queue priority.
The policy bulletin under `policy_bulletins/` is a fictional change request for
the live rules-as-code demo; it has not been applied to the active rules.

All patients, payers, remittances, notes, and dollar amounts in this repository
are synthetic and fictional. This is decision support, not a substitute for
professional judgment; a clinician or biller approves every letter before
submission.

## Evaluation

`python eval/run_eval.py` compares parsed and triaged cases to hand-authored
scenario labels and writes `eval/report.md` and `eval/report.json`. Labels are
not generated by the triage implementation.

## Demo script

1. Show the prioritized queue at `/api/queue`.
2. Open the top appeal in `/api/denials/{id}` and inspect its generated letter.
3. Upload a new 835 remittance to `POST /api/denials`.
4. Run the synthetic evaluation with `python eval/run_eval.py`.
5. Live: Devin applies the Acme bulletin and opens a PR updating the rules and
   corresponding tests.
